# 문장배틀 카드 제시 통합 시방서 v1.2
개정일: 2026-11-14 | 적용 범위: 모든 초급·중급·고급 문장배틀 문항과 이후 제작 단원

## 0. 최상위 필수 규칙 — 문장마다 카드 최소 4장
이 규칙은 기존 v1.0의 초급/중급 권장 분절 방식보다 우선 적용한다. 출제되는 모든 문항의 카드 수는 반드시 4장 이상이어야 한다.

1. 1차 분절: 교재 수준에 맞는 의미 단위와 핵심 문법 표현을 유지하며 카드를 만든다.
2. 4장 미만이면: 먼저 분리 가능한 어휘와 조사(은/는/이/가/을/를/에/에서/에게/한테/으로/로/도 등)를 별개의 카드로 만든다. 중급 단계도 이 경우 조사 분리 예외를 허용한다.
3. 불가 분리: 안/못 부정 부사와 서술어, 동사·형용사의 연결/종결어미, 핵심 문법 덩어리(-는 것, -(으)ㄹ 줄 알다, -지 않다, -(으)ㄹ 텐데, -는데도 불구하고 등)를 임의로 찢지 않는다. 현행 학생 화면에서 조사의 자석 결합이 지원되지 않는 경우(예: -이나)에는 무리하게 분리하지 않는다.
4. 그래도 4장 미만이면: 같은 단원 수준, 어휘 및 핵심 문법을 유지하는 자연스러운 새 문장으로 교체한다. 문항 ID와 순서는 보존하고 기존 문장·교체문·사유를 대조 기록한다.
5. 원문 보존: 교재 원문 JSON은 수정하지 않는다. 비운영 분절표의 승인된 교체문을 사용하고, 교사 화면의 표시 문장·학생 완성 문장·정답 경로가 일치하도록 단일 연결 패치로 보장한다.
6. 교사 직접 추가/문장 수정: 신규 저장하는 문장 역시 최소 4장을 통과해야 한다. 기존 Firebase/PC 영구 저장 문장은 별도 검수 전 자동 변경하거나 삭제하지 않는다. 모든 실제 저장 문항의 통합 전수 검증은 최종 배포 전에 진행한다.
7. 매 차수 자동검증: 누적 전체 4장 미만 0건, 원문/교체문 정확 재구성, 카드 ID 고유성, 정답 경로, 지난 차수 불필요 변경 0건, 신규 원문과 GitHub 직접 대조, 비대상 교재/교사 저장 내용 무변경.
8. 안전/배포: 운영 GitHub main·Firebase·학생 데이터·점수·순위·인증·다른 검임은 최종 교사 승인 전 변경하지 않는다. 실제 학생 휴대전화 및 교사 PC 통합검증은 전체 분절 완료 후 별도 진행한다.

이후 원래 시방서의 기능 설명은 유지하되, 충돌 시 이 v1.2 최상위 필수 규칙을 적용한다.

## Original v1.0 reference text (retained; v1.2 takes precedence)

## 한국어 문장 카드 배열 학습 시스템 기능 시방서 (개정판)

### 1. 시스템 개요 및 목적

* **개요:** 외국인 학습자를 위한 터치 기반 한국어 어순 및 문장 구성 훈련 웹 애플리케이션 모듈.
* **학습 목표:**
* **레벨 1 (초급: 서울대 한국어 1A ~ 2A):** 체언-조사 결합 원리(받침 규칙), 부사의 자연스러운 위치, 기본 복문의 골격 어순 체득.
* **레벨 2 (중급: 서울대 한국어 2B 이상):** 복문(관형절, 인용절, 연결어미 절)의 구조화 및 유창성 훈련.

### 2. 품사 및 어휘 유형별 카드 분절 표준 규격

| 구분 | 요소 | 레벨 1 (1A ~ 2A) | 레벨 2 (2B 이상) | 비고 |
| --- | --- | --- | --- | --- |
| **체언 + 조사** | 주어/목적어/부사어 등 | **명사 / 조사 분리**<br>

<br>(예: `[한국어]` `[를]`) | **어절 결합**<br>

<br>(예: `[한국어를]`) | 레벨 1은 공백 없는 자석 결합(Snap) 처리 |
| **시간·접속 부사** | `어제`, `오늘`, `그리고` 등 | **단독 카드**<br>

<br>(예: `[어제]`) | **단독 카드**<br>

<br>(예: `[어제]`) | 문두 또는 주어 뒤 복수 위치 허용 |
| **정도·양태 부사** | `아주`, `열심히`, `잘` 등 | **단독 카드**<br>

<br>(예: `[열심히]`) | **서술어/절 결합**<br>

<br>(예: `[열심히 공부해서]`) | 총 카드 수 7개 초과 시 서술어 결합 허용 |

<br>(예: `[안 먹었어요.]`) | **서술어 결합 필수**<br>

<br>(예: `[못 갔어요.]`) | 목적어 앞 오배치 방지를 위해 분리 금지 |
| **서술어 (용언)** | 종결형/연결형 | 기본 청크 유지<br>

<br>(예: `[온다고 전해주세요.]`) | 마침표(`.`), 물음표(`?`) 포함 |

### 4. 인터랙션 및 프론트엔드 제어 로직

#### 4.1 슬롯 영역 시각 렌더링 (자석 결합)

* 사용자가 카드를 터치하여 슬롯으로 올릴 때, `attachToPrev: true`인 토큰은 직전 카드와 결합합니다.
* 부사(`adverb`) 및 어절(`noun_phrase`, `clause`)은 항상 좌우 공백(Margin)을 유지합니다.

```javascript
function renderAnswerSlot(placedTokens) {
  let html = "";
  
  placedTokens.forEach((token, index) => {
    // 직전 토큰이 존재하고 현재 토큰이 결합형 조사일 때
    const isSnap = token.attachToPrev && index > 0;
    const spacingClass = isSnap ? "snap-attached" : "card-gap";
    
    html += `<span class="placed-card type-${token.type} ${spacingClass}" data-id="${token.id}">
               ${token.text}
             </span>`;
  });
  
  return html;
}

```

#### 4.2 예외 처리 및 오조작 방지

1. **단독 조사 선배치 금지:**
* 슬롯이 비어 있거나 직전 카드가 체언(`noun`)이 아닐 때 `particle` 카드를 터치하면, 슬롯에 추가되지 않고 해당 카드에 `shake` 애니메이션을 출력합니다. (예: 부사 `[어제]` 바로 뒤에 목적격 조사 `[를]`을 붙이려는 시도 차단)


2. **부사 인접 제약:**
* 정도/양태 부사(`열심히`, `아주`) 뒤에 바로 조사가 붙을 수 없도록 입력 순서를 엄격히 검증합니다.


3. **체언 카드 취소 시 연동 반환:**
* 슬롯에 이미 결합된 명사-조사 쌍 중 명사를 클릭하여 취소할 경우, 뒤에 붙은 조사 카드도 함께 하단 카드 풀(Pool)로 자동 회수합니다.



---

### 5. 정답 검증 엔진 (Validator)

* **배열 비교 로직:**
* 텍스트 문자열 단순 합치기가 아닌, 고유 `token.id`의 순서 배열을 대조하여 채점합니다.


* **복수 어순 자동 판정 (부사 위치 규칙):**
* 시간 부사는 **문두(Index 0)** 또는 **주어 직후(주어 조사 뒤)** 배치를 모두 정답 배열(`validPaths`)에 기본 등재합니다.
* 서술어 바로 앞의 양태 부사(`열심히`, `잘`)는 서술어 직전 위치를 기본 원칙으로 삼습니다.
